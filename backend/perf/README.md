# Нагрузочное тестирование backend при помощи k6

В директории `backend/perf/k6` расположен сценарий, моделирующий типичный жизненный цикл работы с доской Kanban: аутентификация, создание доски, чтение, обновление и удаление. Сценарий можно использовать как для смоук-проверок после изменений в API, так и для базовой оценки производительности под нагрузкой.

## 📦 Требования

- Запущенный экземпляр CollabBoard backend (локально через `go run`, `docker compose` или в тестовом окружении)
- [k6](https://k6.io/docs/getting-started/installation/) версии 0.46 или новее
- Тестовый пользователь с правами по умолчанию (создаётся автоматически скриптом, если не существует)

## ⚙️ Переменные окружения

| Переменная | Значение по умолчанию | Назначение |
|------------|-----------------------|------------|
| `K6_BASE_URL` | `http://localhost:8080` | Базовый URL backend API |
| `K6_USER_EMAIL` | `loadtest+<timestamp>@example.com` | Email пользователя для нагрузочного теста |
| `K6_USER_PASSWORD` | `P@ssw0rd!` | Пароль тестового пользователя |
| `K6_USER_NAME` | `Load Tester` | Имя, использующееся при регистрации |
| `K6_MAX_VUS` | `20` | Максимальное количество виртуальных пользователей (VU) во время пика нагрузки |
| `K6_ITERATION_SLEEP` | `1` | Пауза (в секундах) между итерациями каждого VU |
| `K6_FAIL_ON_SEED_ERROR` | `false` | Если `true`, тест завершится с ошибкой при нештатной проблеме регистрации тестового пользователя |

> ℹ️ При первом запуске скрипт создаёт пользователя по указанным реквизитам и переиспользует его для всех последующих запусков.

## ▶️ Запуск теста

1. Запустите backend и убедитесь, что он доступен по адресу, указанному в `K6_BASE_URL`.
2. Выполните команду:

```bash
k6 run backend/perf/k6/board-workflow.js
```

Для запуска с кастомными параметрами используйте переменные окружения, например:

```bash
K6_BASE_URL=http://localhost:8080 \
K6_USER_EMAIL=loadtest@example.com \
K6_USER_PASSWORD=Secret123! \
K6_MAX_VUS=50 \
k6 run backend/perf/k6/board-workflow.js
```

## 📄 Отчёт по итогам прогона

Сценарий сохраняет краткий JSON-отчёт в `backend/perf/k6/summary.json`, что удобно для последующего анализа или интеграции с CI/CD. Дополнительно статистика выводится в стандартный поток вывода в удобочитаемом виде.

## 🧪 Расширение сценариев

- Используйте `group` и `check` для добавления новых шагов (например, работу с колонками и карточками).
- При необходимости можно задействовать [scenarios](https://k6.io/docs/using-k6/scenarios/) для моделирования нескольких типов нагрузки (например, чтение/запись).
- Для генерации сложных данных пригодятся утилиты из [jslib.k6.io](https://jslib.k6.io/).

## 🔁 Автоматизация

В корневом `Makefile` добавлена цель `k6-load-test`:

```bash
make k6-load-test
```

Она проверяет наличие бинарника `k6` и запускает сценарий с текущими переменными окружения. Это позволяет легко встроить нагрузочное тестирование в CI/CD или использовать его локально одним вызовом.
